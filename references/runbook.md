# 自动切期与配置检查 Runbook

## 任务输入

```text
sheetScope: 用户指定的一个或多个工作表
oldPeriod: 旧期列名或期号规则（例如 0827期）
newPeriod: 新期列名或期号规则（例如 0903期）
idSource: 表格单元格值
linkSource: 超链接目标优先；必要时使用纯文本 URL
```

若旧期/新期未明确，按表头提取“数字+期”，按期号排序后提出候选；不得直接执行。

## 状态定义

- `待检查`
- `检查通过（旧ID唯一且新ID不存在）`
- `旧新ID同时存在，需人工确认`
- `未找到旧ID`
- `多匹配需人工确认`
- `缺少字段`
- `链接异常`
- `页面结构异常`
- `登录状态异常`
- `预览完成，待确认`
- `执行中`
- `成功`
- `替换失败`
- `保存失败`
- `检查失败`

Level 1 的“检查通过”只表示页面状态符合任务前置条件，不代表已修改。

## 每行流程

1. 固化当前行上下文：`sheetName + rowNumber + oldId + newId + configUrl`。
2. 读取 URL 并验证登录、页面加载、编辑器/保存区域存在。
3. 扫描页面可见字段和嵌套编辑器字段，统计旧ID、新ID的精确出现次数及位置。
4. 旧ID为 0：标记未找到并停止；大于 1：列出全部位置并暂停。只有用户明确确认“这些匹配都应替换”后，才允许批量替换。
5. 旧ID唯一时生成预览，必须展示字段标识、完整旧值和替换后的完整值。
6. 执行前重新核对当前页面仍对应同一 URL、旧值仍等于预览值、新值仍等于当前行新ID。
7. 获得动作时确认后，仅填充预览中的目标字段并保存/提交。批量执行时，确认内容必须包含完整批次范围和每行映射。
8. 保存后重新加载页面，确认旧ID不存在、新ID存在、目标字段值正确、保存成功信号可见。批量执行必须逐行记录复查结果。
9. 写入日志并继续下一行；任一行异常时暂停该行及后续批次，不自动跳过。

## 日志字段

```text
timestamp, sheetName, rowNumber, oldId, newId, configUrl,
mode, status, errorReason, beforeSnapshot, afterCheck,
saveSignal, screenshotOrSnapshot
```

## 特殊规则

- 一个页面出现多个相同旧ID时，默认暂停；用户明确确认所有列出的位置均应替换后，才可批量替换，并逐位置复查。
- 跨多行批量替换必须保留每行独立的旧ID/新ID/链接绑定和预览，不得合并成模糊的全局查找替换。
- 新ID已存在时不要假设任务已完成；记录“旧新ID同时存在，需人工确认”。
- 旧ID缺失但新ID存在，不能自动标记成功；需用户确认是否已由人工完成。
- 不能确认保存结果时标记保存/检查失败，不重试写入。
